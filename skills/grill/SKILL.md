# grill: 작업 전 질문으로 맞추기

## 설정
시작할 때 `<이 스킬 폴더>/../autoEnterEnter/references/settings.md`로 DOCS(문서 위치)·BASE(기준 브랜치)·RULES(규칙)·COMMIT(커밋 형식)을 정하고 한 줄로 알린다.

## 목표
코드를 보기 전에, 이번 작업이 무엇을 처리하고 무엇을 처리하지 않는지를
사용자와 하나씩 확정한다. 질문이 끝날 때까지 코드는 쓰지 않는다.

## 시작 전에 직접 찾을 것 (묻지 않는다)
- 관련 이슈·PR 본문 (`gh issue view`, `gh pr view`, 읽기만)
- 관련 코드, RULES의 규칙 문서
- 메모리의 관련 항목 (이전 결정, 회의 안건)
- 위에서 답이 나오는 건 질문하지 않고 "확인한 사실"로 먼저 짧게 알린다.
- 근거 순서: ① RULES의 규칙 → ② BASE에 이미 머지된 코드 → ③ 이슈 본문 → ④ 열린 PR은 참고만.
  위가 아래보다 앞선다. 열린 PR을 "팀 기준"으로 쓰지 않는다. (머지 안 된 PR을 따라가면 규칙과 어긋나기 쉽다)
- 이슈가 있으면 첫 질문 전에 **이슈 체크리스트 표**를 출력한다.
  | 줄 | 이슈 내용 | 상태(이미 정해짐 / 정할 것 / 후속으로 명시) |
  줄마다 #1, #2 … 번호를 붙이고, 이후 질문과 결정에 이 번호를 단다. (이슈와 대조하지 않으면 PR을 올린 뒤에야 빠진 것이 드러난다)
- 문서끼리 어긋나면 고치지 말고 알리기만 한다.

## 질문 순서
1. 이번 작업에서 정해야 할 결정 목록을 머릿속으로 만든다.
2. 다른 결정의 전제가 되는 것부터 묻는다. (용어 → 범위 → 동작 → 예외 → 테스트)
3. 동작이 바뀌지 않는 취향 문제는 묻지 않고, 가까운 규칙대로 정한 뒤 끝에 알린다.
4. 묻는 건 **동작이 바뀌거나 이슈가 요구하는 것**만이다. 지금 필요 없는 세부(예: 파티션 수)는
   묻지 않는다. 반대로 이슈 대조, 뺄지 말지 같은 큰 결정은 반드시 묻는다.

## 질문 하나의 형식
한 번에 **질문 하나만** 한다.

    **Q3. <한 줄 질문>**  (이슈 #2)
    - 추천: <결론 한 줄>
    - 왜 묻나: <이게 안 정해지면 무엇이 갈리는지>
    - 예시: <숫자 예시. 예: 판매가 10,000원, 수수료 10%일 때 ...>
    - 선택지:
      - A. ... (추천): <이유>
      - B. ...: <언제 이게 나은지>
    - 메모리·규칙 근거: <있으면>

- `(이슈 #N)`은 이슈 체크리스트 줄 번호다. 이슈와 무관한 질문이면 생략한다.
- 추천을 맨 앞에 한 줄로 쓴다. 결론을 뒤로 미루지 않는다.
- 추천은 레포 규칙을 따르는 안을 우선한다.
- 사용자가 "모르겠어", "나중에"라고 하면 TODO(확인 필요)로 적고 다음으로 넘어간다.

## 용어
- 처음 정한 용어를 끝까지 쓴다. 같은 대상을 다른 이름으로 부르지 않는다.
- 새 용어가 정해지면 다음 질문 앞에 `용어: <이름> = <뜻>` 한 줄로 남긴다.

## 답을 받은 뒤
- "정리: <결정 한 줄>"로 확인하고 다음 질문으로 넘어간다.
- 앞의 답과 부딪히면 넘어가지 말고 그 자리에서 짚는다.

## 끝낼 때
사용자가 "끝", "그만"이라고 하거나 결정이 다 정해지면 아래만 출력한다.

    ### 확정한 것
    | # | 결정 | 이유 |
    ### 용어
    ### 처리하지 않는 것
    ### TODO(확인 필요)
    ### 회의 안건 후보

- 메모리 저장, 이슈 댓글, 코드 작성은 각각 사용자가 하라고 할 때만 한다.

## 하지 않는 것
- 코드·문서 수정, 커밋, 서브 에이전트 실행
- 질문 여러 개를 한 번에 쏟아내기
- 사용자가 메모리·CLAUDE.md에서 언급하지 말라고 정한 주제를 질문으로 꺼내기
