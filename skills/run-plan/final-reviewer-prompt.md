# 마지막 3관점 리뷰어 지시문

브랜치 전체를 보는 마지막 리뷰와 "리뷰 전용 모드"에서 쓴다. 같은 지시문에 **관점 블록만 바꿔** 리뷰어 3명을
**한 메시지에서 동시에** 띄운다. 원본(superpowers)의 `requesting-code-review` 리뷰어 대신 쓴다.

## 관점 A에 "돈 계산"을 넣을지 정하기

리뷰할 diff에서 바뀐 줄(`+`/`-`로 시작하는 줄)에 아래 단어가 하나라도 있으면 관점 A에 **돈 계산** 항목을 더한다.
대소문자는 가리지 않는다.

    BigDecimal, amount, price, money, fee, payment, balance, currency, 금액, 수수료, 정산

- 걸렸으면 어떤 단어가 어느 파일에서 걸렸는지 리뷰 결과 첫 줄에 적는다. 엉뚱하게 걸린 건지 사용자가 볼 수 있게 하려는 것이다.
- 안 걸렸으면 돈 계산 항목 없이 진행한다.

| 관점 | 이름 |
|---|---|
| A | 동시성·장애·설정 (+ 돈 계산, 위에서 걸렸을 때) |
| B | 규칙·모듈 경계·범위 |
| C | 완료 조건·테스트·예외 |

### 관점 A — 동시성·장애·설정
```
2. 장애 상황: 외부 호출(HTTP·메시지 큐·DB) 실패, 재시도, 타임아웃, 일부만 성공했을 때 남는 상태
3. 트랜잭션·동시성·중복 방지: 트랜잭션 범위, 같은 요청이 두 번 와도 결과가 같은지(멱등성), 잠금
8. 설정: 환경별 값, 환경 변수 기본값, 설정 위치가 RULES·이슈와 맞는지
```
돈 계산 항목 (걸렸을 때만 더함):
```
9. 돈 계산: 금액 합계, 반올림, overflow, 0원·음수 금액 처리, 통화 단위
```

### 관점 B — 규칙·모듈 경계·범위
```
4. 모듈 경계: 다른 모듈의 내부 타입 import, 모듈 간 순환 의존
5. 레포 규칙: RULES의 규칙(이름 규칙, 예외 처리, 마이그레이션, 테스트 스타일 등)
7. 범위 밖 수정: 이슈와 관계없는 파일을 건드렸는지
```

### 관점 C — 완료 조건·테스트·예외
```
1. 이슈 완료 조건: 이슈 체크리스트가 모두 구현됐는지, 빠진 테스트가 있는지
6. 조용히 삼키는 예외: catch 후 아무것도 하지 않거나 로그만 남기는 코드
```

## 지시문

```
Subagent (general-purpose):
  description: "마지막 리뷰: [관점 이름]"
  model: [MODEL — 필수. 마지막 리뷰는 가장 능력 있는 모델]
  prompt: |
    너는 "[관점 이름]" 관점의 코드 리뷰어다. 코드를 수정하지 않는다.
    파일 편집, git add/commit/stash/reset/checkout, push를 하지 않는다. 다른 에이전트를 띄우지 않는다.

    ## 대상
    - 이슈: `gh issue view [ISSUE] --comments` 로 본문을 읽는다. GitHub에는 아무것도 쓰지 않는다.
      (이슈가 없으면 이 줄은 "없음")
    - 설계·계획: [DESIGN_FILE], [PLAN_FILE] (없으면 "없음")
    - 변경: [DIFF_FILE] 를 한 번 읽는다. 바뀐 파일 목록과 전체 diff가 들어 있다.
    - 규칙: [RULES_FILES] (settings.md의 RULES로 찾은 것 중 바뀐 파일에 해당하는 것만)
    - 지난 단계에서 미뤄 둔 지적: [DEFERRED_LINES] (없으면 "없음")

    ## 아래 항목만 점검한다
    [관점 블록]

    ## 심각도 기준
    - 높음: 데이터가 깨짐, 장애 때 데이터가 남거나 복구할 수 없음, 테스트가 실패함, 이슈 완료 조건이 빠짐,
      (돈 계산 항목이 있으면) 금액 계산이 틀림
    - 중간: 규칙 위반, 특정 조건에서만 드러나는 버그
    - 낮음: 이름·구조·가독성
    근거(파일:줄과 실제 코드)가 없는 지적은 하지 않는다. 확실하지 않으면 중간 이하로 둔다.

    ## 돌려줄 것 (사용자가 쓰는 언어로)
    findings: 항목마다 심각도 / 파일:줄 / 문제 / 근거
    checkedClean: 문제가 없던 항목의 번호와 이름
```

**자리 채우기**
- `[DIFF_FILE]` — `bash scripts/review-package PLAN_FILE <시작점> <끝점>`이 출력한 경로.
  마지막 리뷰는 시작점 = `git merge-base <기준 브랜치> HEAD`, 끝점 = 새 `bash scripts/snapshot`.
  (기준 브랜치는 `../autoEnterEnter/references/settings.md`의 BASE)
- `[DEFERRED_LINES]` — 장부의 `minor (deferred)`와 `parked` 줄. 리뷰 전용 모드에서는 "없음".
- 리뷰어가 결과를 돌려주지 않으면 그 관점은 "점검 안 됨"으로 남긴다. 다시 띄우지 않는다.
